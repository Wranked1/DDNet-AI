## Порядок работы

- Разделять ошибки, архитектурные ограничения и необязательные эксперименты; не включать все опции вслепую.
- Текущее ограничение владельца: только статический анализ/правки, без запуска бота и тестов. Динамическая оценка ниже — будущая работа после изменения этого ограничения.

## Стоящие улучшения

| Идея | Реализация | Зачем |
|---|---|---|
| Учить реакции конкретного игрока | Хранить «ситуация → наше действие → его ответ → исход». | Предугадывать контратаки. |
| Помнить повторные провалы | Снижать приоритет неудачной комбинации в похожем контексте. | Не отдавать дуэли одному контрприёму. |
| Разнообразить безопасные планы | Смешивать только близкие по качеству варианты. | Меньше предсказуемости без случайных самоубийств. |
| Отслеживать смену тактики | Взвешивать свежие наблюдения и ослаблять устаревший профиль. | Адаптироваться к адаптации человека. |
| Сохранять профили между дуэлями | С проверкой идентичности/уверенности, не полагаясь безусловно на ник. | Накапливать полезный опыт. |
| Планировать дожим к разморозке | Готовить позицию, молот и ответ на попытку спасения. | Не отпускать пойманного. |
| Искать устойчивые атаки и приманки | Проверять контрходы; провоцировать только подтверждённые привычки. | Создавать трудные для спасения положения. |
| Выбирать позицию и цель по угрозе | Угроза → доступное добивание → сила; сохранять путь отхода. | Не гоняться за сильнейшим ценой собственной гибели. |
| Сверять прогноз с наблюдением | При ошибках модели увеличивать запас безопасности. | Меньше провалов из-за задержек/неточной физики. |
| Распределять вычисления по опасности | Больше просчёта у freeze и при контакте, меньше вдали от боя. | Точность в решающие моменты при ограниченном CPU. |
| Координировать двух ботов, если используются | Разделять удержание и добивание. | Меньше взаимных помех. |

## Критерии будущей оценки

- Сравнивать с исходной версией на разных картах, пингах и стилях соперника, включая повторные дуэли с одним игроком.
- Измерять self-freeze, упущенное добивание, точность прогноза, время решения и результат матчей, а не только награду собственного симулятора.
- Для каждого пункта фиксировать: подтверждено / исправлено / отклонено с причиной / осталось. Не обещать непобедимость.
